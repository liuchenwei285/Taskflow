## 二、作品是什么

一句话：**Taskflow 是一个"资料 → 试卷 → 计时任务"的学习工作台。**

大多数计时 App 管理的是"时间"，但学生缺的往往不是时间，而是"这段时间到底做什么"。Taskflow 把这件事接了起来：

> 上传笔记 → 本地解析 → 提取知识点 → AI 出题 → 估算用时 → 确认创建任务 → 开始倒计时 → 导出试卷 → 存入试卷库

整条链路在**同一个对话框**里完成，不跳页、不填表。试卷不是终点：它会带着"预计 37 分钟"这样的估时，变成任务页里一条真正能开始、暂停、完成的倒计时任务。**出题和执行，在一个闭环里。**

![学习工作台首屏：一句话安排今天 + 今日待办](https://static.tianchi.aliyun.com/userimg/1095281247727/2026-11-20/9vxSbkv0nqzl5oL1.png)

打开网站的第一屏就是工作台本身：一个输入框、三个引导 chip（"上传资料，出一套试卷 / 把复习排成每日任务 / 拆解今晚的作业"）、和今天的待办。没有营销页，没有注册墙。

**AI 是加速器，不是发动机：不配密钥时的完整基础功能。** 不配置任何模型接口，以下全部是真实可用的功能，不是演示占位：

- **手动创建与全生命周期**：标题 / 备注 / 优先级；「任务（预计时长 + 截止时间）」与「番茄钟（经典 25+5、深度 50+10、自定义轮数）」两种时间模式；保存后默认「待开始」，由你自己按下开始；暂停 / 继续 / 完成 / 到期五状态迁移全部本地计算，暂停不计入用时、刷新不丢进度。
- **提醒与提前预警**：逐任务提前预警（不预警 / 剩 1 / 5 / 10 分钟），到期提示音 + 系统通知（关闭后仍弹页面内提醒）；已到期任务可延期、修改截止或完成。
- **组织与回顾**：搜索（含中文输入法组合路径）、排序、分组、状态筛选；统计页周柱状图与全年热力图由你的真实专注记录汇总。
- **学习工作台的本地一半**：.txt / .md 上传、SHA-256 内容指纹去重、分节解析与预览都在浏览器内完成；只有「出题」一步需要 AI。
- **试卷库与导出**：已存试卷的查看、管理、删除，以及 PDF / PNG / Markdown / JSON / CSV 五种真实文件导出，均不依赖 AI；删除试卷不会删除由它创建的任务。
- **数据与体验底面**：备份一键导出 / 导入（导入前自动先备份当前数据一次）；深色 / 浅色、自定义强调色、中英双语、减少动效、320px 窄屏照常可用；单文件零 CDN，断网打开本地副本公式渲染与导出不失效。

![不配 AI 的手动新建：优先级、任务/番茄钟双模式、预计时长与截止时间可同时设置](https://static.tianchi.aliyun.com/userimg/1095281247727/2026-11-20/iRJv6JyRYtlosxjr.png)

一句话：**不配 AI，它是一个完整、可离线使用的学习计时工作台；配上 AI，它才多出「笔记 → 试卷 → 任务」这条加速器。**

## 三、为什么做它

三个我自己真实踩过的坑：

1. **资料在手，无题可刷。** 笔记整理了三十页，但找不到对应章节的练习题；等找到题，复习节奏已经断了。
2. **计划写完，执行归零。** "今晚复习高数第三章"写在便签上，没有开始按钮、没有剩余时间、没有到期提醒，第二天便签还在，复习没发生。
3. **两种时间被混为一谈。** 很多工具把"距截止还有多久"当成任务倒计时显示：任务还没开始，数字已经在掉，越看越焦虑，却不知道自己实际投入了多少分钟。

Taskflow 对着这三个坑各给了一刀：资料直接变试卷；试卷直接变带计时的任务；**"预计时长"和"截止时间"彻底分成两个语义**——前者是你按下开始后才走的工作计时，后者是自然时间，到点就到期，与你是否开始无关。

## 五、体验与设计上，我做的几个决定

- **首屏即工具。** 第一屏就是输入框和今日待办，评委三秒内知道它能干什么，不需要说明书。
- **写入类动作必须过确认卡片。** 创建任务、删除试卷、覆盖数据，都会在对话里弹确认卡；点取消，**一个请求都不会发出去**。AI 是助手，不是替你签字的人。
- **两种倒计时语义分离 + 五状态状态机。** 待开始 / 计时中 / 已暂停 / 已完成 / 已到期，各有明确的迁移规则：暂停不计入用时、刷新不丢进度、到期自动暂停并保留已用时间、已完成不再判定到期。这套规则写进了任务书，也写进了测试断言。
- **零 CDN，离线可用。** KaTeX 与 html2canvas 全部内联进单文件，不请求任何外部 CDN——教室弱网、内网环境、甚至断网打开本地副本，公式渲染和 PDF 导出都不失效。这一条是被真实故障逼出来的（见第六节）。
- **密钥不上前端服务器、也不上传任务列表。** AI 采用自带密钥直连：密钥只存在你自己浏览器的本地存储，请求从浏览器直发你配置的接口；对话页有明确告知勾选框。接口出错时给的是九类可操作文案（密钥无效 / 额度不足 / 网络超时……）加短错误码和限次重试，而不是一片白屏或一句"请求失败"。
- **深色 / 浅色 / 自定义强调色 / 中英双语 / 减少动效 / 320px 窄屏**，全部是一等公民：两套主题共用同一布局与动效，581 条词条中英同步，强调色一改全跟随。
  ![深色模式统计页：周柱状 + 全年热力图](https://static.tianchi.aliyun.com/userimg/1095281247727/2026-11-20/DF0S46WIyBLPdbXq.png)
  ![移动端横屏深色：新标语、四态统计与到期处理](https://static.tianchi.aliyun.com/userimg/1095281247727/2026-11-20/12pImBhd64K2OWiV.png)
- **一个文件，三种形态。** 整个应用是一个约 1MB 的 HTML（内联 CSS/JS/资源），同一份代码跑在浏览器、Qoder Sites 公网、以及项目自带的 Android WebView 壳里；三份副本逐字节一致，用 md5 校验锁死。

## 六、怎么用 Qoder 做出来的

不是"让 AI 写个网页"然后复制粘贴。我的流程是：**审计 → 任务书 → 实现 → 红线测试 → 部署 → 真实浏览器验收 → 根因修复 → 复验**，每一轮都在 Qoder 会话里留痕。

**① 先审计，再动手。** 第一轮我让 Qoder 通读这个单文件应用，输出结构、数据模型、测试覆盖、部署可行性的审计报告，确认哪些是红线（业务逻辑、倒计时数学、存储键结构），之后所有改动都绕着红线走。

**② 把需求写成结构化任务书，分阶段交付。** 学习 Harness 不是一次 prompt 生成的：产品定位、工具白名单（parse_files / extract_knowledge / generate_questions / estimate_time / plan_tasks / create_tasks / export_file / save_to_library）、确认卡片规则、AI 思考气泡的阶段状态，都先写进任务书再实现。下面是我发给 Qoder 的完整任务书截图：

![Qoder 会话任务书：开发学习 Harness + 试卷库](https://static.tianchi.aliyun.com/userimg/1095281247727/2026-11-20/ONXcP50qMzC7K7fV.png)

**③ 用"已核实问题清单"驱动修复，而不是凭感觉改。** 每轮验收发现的问题，我先复现、记录请求与状态码，再写成修复任务书交给 Qoder。比如下面这份：重复上传出现两张同名卡片、jsDelivr 上的 KaTeX 被客户端拦截（net::ERR_BLOCKED_BY_CLIENT）导致在线渲染无法确认、搜索/排序只断言了控件存在没断言结果……对应的修复是 SHA-256 内容指纹去重（同名不同内容不误合并）、KaTeX/html2canvas 全内联零 CDN、E2E 改为断言真实结果。

![Qoder 会话任务书：基于已核实验证结果的修复清单](https://static.tianchi.aliyun.com/userimg/1095281247727/2026-11-20/KpD9cLewEEq0g8xF.png)

**④ 倒计时语义那次重构，任务书里直接给了状态机。** "卡片最大的数字是距截止倒计时，不是任务时长；用户没有开始选项；已创建但未开始的任务没有地方放"——现状问题、五状态迁移、通知只触发一次、新增字段必须可选且有默认值，全部写明，Qoder 严格按此实现，旧存储字段含义一个没破坏。

![Qoder 会话任务书：修正计时逻辑与待开始板块](https://static.tianchi.aliyun.com/userimg/1095281247727/2026-11-20/dMYs0BITIwJsF3WF.png)

**⑤ 测试是验收门槛，不是装饰。** 14 套 Playwright E2E（真实 Chrome）全绿才允许合并：搜索含 IME 组合输入路径、排序/分组/筛选断言真实结果、通知权限允许与拒绝两条路径、AI 出题 mock 覆盖成功/失败/重试/入库/渲染、欢迎弹窗 71 条断言锁死"不碰用户任务数据"。三份 HTML 副本每次同步后 md5 比对一致。

**⑥ 部署与线上验收也在 Qoder 里闭环。** 通过 Qoder Sites 准备产物、发布公网；每次发布后 Qoder 用真实浏览器打开线上链接逐项复核（标题、标语、尺寸、控制台无报错），复核通过才算交付。本帖所有界面截图均采自**线上公网版本**，不是本地开发服。

体感总结一句：Qoder 对我而言不是代码生成器，而是一个**能被任务书约束、能被测试验收、能被我拿着截图追问根因**的工程同事。我负责定义"什么算做完"，它负责把"做完"变成事实。
